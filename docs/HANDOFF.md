#### 2. OpenAIのAPIには無料枠がありません

これは想定と違う可能性があります。お願いしていたのは
**Groq / Cerebras / OpenRouter の無料枠**でした。

OpenAIのAPIは**前払いのクレジット制**で、残高が無いと
`429 insufficient_quota` を返します。つまり、

* アカウントにクレジットが入っている → 使えます（**有料**）
* クレジットが無い → **1回も呼べません**

「Geminiの1日20回が足りない」という元の問題に対しては、
**有料での解決**になります。無料で枠を増やしたいのであれば、
Groq等の取得を別途お願いしたいです。どちらでも設定できます。

### 直したもの（どれも実際に起きていました）

**1. 数値だからという理由でKPIを作っていた**

```
読書記録の「評価(5段階)」 → 評価の合計       ← 意味を成さない
釣果の「サイズ(cm)」      → 魚の長さの合計   ← 誰も知りたくない
```

「数値である」ことと「足すと意味のある量である」ことは**別**なのに、
型だけで後者を推測していました。数値に**どういう量か**を持たせて、

```
評価   → 平均      （合計は無意味）
サイズ → 最大      （一番大きかった魚）
金額   → 合計
分からない → **KPIを作らない**
```

としました。「分からない」を「合計できる」に倒した瞬間に上の2件が
戻るので、そこは倒しません。

**2. 「今月いくら残っているか」に答えられていなかった**

家計簿に**収入と支出の区別がありませんでした**。金額を全部足しても
残高にはなりません。収支の別を持たせて、

```
残高  ← 画面で一番大きい（収入 − 支出）
収入  ← 収入の色
支出  ← 支出の色（エラーの赤とは別。支出は失敗ではないので）
```

を出せるようにしました。**家計簿用のTemplateを足したのではなく**、
既存の家計簿の「データの形」に欠けていたものを埋めたものです。

**3. 「一番目立たせる」と指定しても、実際には大きくなっていなかった**

`metric.primary`（画面で一番重要な数値）を付けても、**描画は1ピクセル
も変わっていませんでした**。Flutter側の仕組み上、指定が上書きされて
いたためです。同じ理由で「主要ボタン」と「副次ボタン」も見た目が
同じでした。

直したので、主要ボタンは塗りつぶし・副次ボタンは輪郭だけになります。

**4. 暗い画面で意味の色が読めなかった**

色を固定値で書いていたので、Darkでは背景に沈んでいました。
Light/Darkそれぞれの色を持つようにしました。

**5. AIが選んだものと、Forgeが埋めた既定値が混ざっていた**

記録には最終結果しか残っておらず、「AIが選んだ」のか「AIが答えられず
Forgeが埋めた」のかが**区別できませんでした**。このまま学習させると、
**Forgeの既定値をAIの手柄として学ぶ**ことになります。型で分けました。

**6. 「良いDesignかどうか」を誰も見ていなかった**

意味の役割が付いているかを見るだけでは足りません。10個全部が
「一番重要」でも役割は付いています——それは階層が消えた状態です。
乱立・付け忘れ・持ち上げすぎを、Criticが**駄目だと言える**ように
しました。

> なお、これを実装した直後に自分で壊してみたところ、**外してもテストが
> 1件も落ちませんでした**（＝置物）。テストを足して直してあります。

**7. 環境によって動きが違う場所があった**

内部の話ですが、同じコードが「本番では動く / 単体テストでは動かない」
状態でした。テストが何件通っても本番の証拠にならないので、直しました。

### 見た目はどう変わりますか

**家計簿・在庫のような数値を扱うアプリは、はっきり変わります。**
残高が一番大きく出て、収入と支出が別の色で並びます。ボタンの強弱も
出ます。

**まだ変わっていないところ**も正直に書きます。余白・行間・文字の詰めと
いった「完成画像級」の多くが宿る部分には、今回は手を付けていません。
画面の種類も増えていません（Widgetは20種のまま）。
