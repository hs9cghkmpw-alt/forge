## 0. まず、簡単な言葉で

Forge のホーム画面には、利用者が **「Gemini」と「Mock」を指で切り替える
ボタン**が付いていた。これを外し、**「AIモード」**という1つの表示だけに
した。どの AI を使うかは Forge が中で決める。

そのついでに、実際にブラウザで動かして 2 つの嘘を見つけて直した。

1. **お試し用の疑似データが「Generated by Forge」と名乗っていた。**
   本物の AI が作ったものと見分けが付かなかった。
2. **作れなかった部分が、製品版では黙って消えていた。**
   利用者からは「最初から無かった」のと同じに見えていた。

どちらも「画面には出ているのに、中身が違う」種類の不正直さである。

## 0.1 CEO へ報告すべき事故（このタスク中に起きた）

**Claude の作業ホストで、実 Gemini API が呼ばれた可能性が高い。**

ブラウザで実描画を撮るために backend を起動したところ、この作業コンテナの
`backend/.env` に **実 API キーが入っていた**。`/api/v1/ai/converse` を
**2 回** 送信した後にこれに気付き、直ちに backend を停止した。

- 送信回数: 2 回（`鍵の持ち出し…` / `家族で予定を管理したい`）
- 応答は `provider: "gemini"` を返した。この名前は **実際に応答を返した
  Provider** を記録する `last_provider_used` から来ており、呼ばれていなければ
  `"unknown"` になる。したがって **呼ばれたと判断する**
- `generativelanguage.googleapis.com` はこのコンテナから到達可能である
  （キー無しの素の GET で HTTP 404 = Google 自身の応答。Proxy 遮断ではない）
- キーの値は表示・記録・commit していない。`backend/.env` は gitignore 対象で
  git 追跡外である（`git check-ignore` で確認済み）
- 以後このホストで backend を起動しない

無料枠を 2 回分消費させた。報告する。

## 2. 「AIモード」の状態と、実状態の対応

表示は**実状態**に従う。`AiModeState`（`frontend/lib/shared_widgets/ai_mode.dart`）。

| 状態 | 画面の文字 | いつ |
|---|---|---|
| `ready` | `AIモード` | 通常。Forge が経路を選んで AI を使う |
| `working` | `AIが考えています…` | 応答待ち |
| `preparing` | `AIモードを準備しています…` | 接続確認中（実状態未確定） |
| `simulated` | `お試しモード` | **疑似データ。AI に接続していない** |
| `unavailable` | `AIに接続できません` | 接続失敗 |

判定順（`resolveAiModeState`）は**楽観側へ倒さない**向きに固定してある。

```text
unreachable        → unavailable   （観測した事実が最優先）
mockBuild          → simulated     （ビルド自体が疑似なら、Backend の返事より優先）
backend simulated  → simulated
busy               → working
それ以外            → ready
```

`isRealAi` は `ready` / `working` だけ `true`。**`simulated` を `true` に
しない**ことがテストで固定されている。

## 3. 消したのは表示だけである

Provider 名を履歴・Evidence から一括削除してはならない（指示 §9）。
今回消したのは **利用者の画面に出る文字だけ**である。

| 場所 | 実 Provider 名 | 理由 |
|---|---|---|
| 通常 UI（Text / Tooltip / Semantics） | **出さない** | Constitution §4・§9 |
| `ErrorEnvelope.message`（利用者が読む） | **出さない** | 同上 |
| `exc.message`（内部） | **残す** | 診断に要る |
| ログ | **残す** | `redact_provider_identity_for_logs` は鍵だけ落とす |
| Evidence / `providerUsed` / diagnostics | **残す** | 実測記録の正確さ |
| Provider 実装のクラス名・Registry 識別子 | **残す** | 実装である |
| 過去の実測記録・report | **触っていない** | 履歴を書き換えない |

`providerUsed` は保存されているが**どの画面にも表示していない**（変更前から）。
この Evidence と UI の分け方は正しいので、そのまま維持した。

## 4. 開発者はどうするか

`--dart-define=FORGE_DEVELOPER_MODE=true` でビルドしたときだけ、
`DeveloperProviderOverride`（Provider 明示指定のプルダウン）が出る。
既定は `false` で、既定ビルドでは `SizedBox.shrink()` を返す。

**実行時に切り替えられる仕組みにしなかった**のは、切り替え経路が製品ビルドに
残っている限り、いつか誰かが辿り着くからである。

開発者ビルドでも疑似出力は疑似出力として表示する（抜け道にしていない）。

## 10. 今回見つけて、直していない問題（新規 TD）

### TD104. 呼んでいない Provider の名前を Evidence が名乗る

`/api/v1/ai/converse` の fast path（LLM 0 回）でも、応答の `provider` が
`"gemini"` になる場面を実機で観測した。`provider` フィールドは利用者へ表示
していないので**表示の問題ではない**が、**Evidence の正確さの問題**である。
「呼んでいないものを呼んだことにしない」は実測と公称を分ける原則そのもの。

Provider 帰属の直しは Pipeline 側の変更になり、今回の UI 範囲を超えるため
分離した。§0.1 の事故により実機での追試もできていない。

## 11. 自己監査（PRODUCT-DIRECTION §8 の 7 問）

1. **会話が製品になっているか** — 会話の入口を壊していない。むしろ利用者が
   Provider を選ぶという「会話でない作業」を1つ消した。
2. **Forge が考えているか** — Provider 選択を利用者から Forge へ戻した。
3. **最小限の道具か** — Scope を縮めていない。UI の選択肢を減らしただけ。
4. **Capability を Widget/Template と同一視していないか** — Widget も
   Template も増やしていない。
5. **自由度のために安全を捨てていないか** — 捨てていない。TD92 は
   fail-open（無言消失）を fail-visible へ倒した。
6. **Local First / Provider 独立か** — 前進した。UI から Provider 依存が消え、
   Router の Local-first / fallback には触れていない。
7. **Mock・未計測・文書だけを実成功にしていないか** — していない。実描画で
   見つけた 2 件を直し、実測できていない項目は §9 に列挙した。
