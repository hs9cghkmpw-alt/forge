FORGE-019A · Semantic Design Revision

「残高をもっと目立たせて」と言うと、こう変わる

いま Forge が作るアプリの見た目と、利用者のひとことで起きる変更です。 左が変更前、右が変更後。右の画面は本番のコードが実際に返した文書から描いています。

! これは Flutterのスクリーンショットではありません。この作業環境には Flutter SDK が無いため、 実機描画は行えていません（UNVERIFIED）。ここに出ている文書・role・色・文字サイズは、 すべて本番のコードと実際の生成物から取った値ですが、実際のピクセルを見たわけではないという 区別は残します。実描画はCIとCEO環境での確認が要ります。

変わったのは2箇所だけ

Forge は文書全体を作り直しません。意味の役割（style_role）だけを、対象を特定して書き換えます。 触っていない場所は1バイトも変わらないので、「直したら別のところが壊れた」が構造的に起きません。

widget意味変更前変更後
balance残高 metric.secondary metric.primary
income収入 metric.primary finance.income
expense支出 finance.expense（変更なし）
summary_header見出し text.headline（変更なし）
list_header / transaction_1 / transaction_2一覧 変更なし

収入が metric.primary のままだと「一番大事な数値」が2つになり、階層が消えます。 かといって state.danger（危険）へ落とすのも誤りです——支出も収入もエラーではないので、 Forge はお金の向きを表す別の語彙（finance.*）を持っています。

いまの見た目についての所見

  • 階層は成立している。 主KPI（36px/w700）→ 収入・支出（16px/w600 + 意味色）→ 一覧（13.5px）と3段に割れており、残高が最初に目に入る。
  • 数字は tabular figures。 桁が変わっても位置が揺れない（193,000 → 99,000 で行が動かない）。
  • 支出が赤系（#C2185B）だが、エラー色（error）とは別トークン。 家計簿を開くたびに「失敗」に見えないようにしてある。
  • まだ弱いところ: 収入と支出が同じ字サイズで並ぶので、2つの関係（収入 − 支出 = 残高）が見た目からは読めない。ここは今回の対象外。
